# 测试说明

## 一、怎么跑

```bash
npm test          # 等价于 node --test test/（Node 20 内置测试框架，零依赖）
```

- **全部离线**：扶摇 API 与大模型都用注入的模拟 `fetchImpl` 代替，按 URL 路由返回**构造数据**（确定性公式生成，不是真实行情的拷贝）。
- **不使用任何真实 Key**：测试里的 Key 是 `test-key-not-real`；`test/helpers.js` 被引入时会把全局 `fetch` 替换成「禁止外网」，一旦有代码绕过注入的 fetch 去访问真实网络，测试立即失败。
- 测试不读取 `.env`（不引入 `src/config.js`、`server.js`）。

### 2. 数据缺失 / 接口失败

| 场景 | 用例 | 预期 |
|---|---|---|
| 业务错误码 2004 / 2001 / 5003 | `fuyao.test.js` | 返回结构化错误（code、message、request_id），不抛异常；已知错误码提示不重复拼接原文 |
| HTTP 429 限流 | `fuyao.test.js` | 退避后只重试一次；连续限流返回 4001，不无限重试 |
| 超时 / 网络错误 / 非 JSON | `fuyao.test.js` | 分别返回 TIMEOUT / NETWORK / BAD_JSON |
| 未配置 Key | `fuyao.test.js` | 不发请求，返回 NO_KEY |
| 缓存 | `fuyao.test.js` | 同 URL 命中缓存 `cached=true`；参数不同不命中；失败结果不进缓存 |
| 资金面接口外部不可用（2004） | `regime.test.js`、`research.test.js` | 成交额预测、宽基 ETF 净申购作为两个缺口展示；调用轨迹里计 2 次失败 |
| 宽度接口失败 | `regime.test.js`、`research.test.js`（breadth_missing） | 出现缺口证据（含失败原因与 code），不生成宽度标签，状态名标注“宽度未知”，置信度下降 |
| 核心数据（指数日 K）失败 | `regime.test.js`、`research.test.js`（fuyao_down） | `report.blocked = true`，不输出研判结论，状态为“数据不足，无法判定”，置信度“低”；主要矛盾不得声称“各维度一致” |
| 数据冲突 | `regime.test.js`、`research.test.js`（conflict） | 快照与日 K 同日相差 > 0.3% 产生冲突证据，置信度扣 0.1 并写明原因 |
| 数据过期 | `regime.test.js`、`research.test.js`（stale） | 置信度下降，原因中写明“数据时点过期” |
| 历史时点 | `research.test.js` asOf | 快照类工具（指数快照、全市场宽度、估值、快讯）状态为 `unavailable`，不用最新值冒充；日 K 不含研判时点之后的数据；完整度不足时不给“高”置信度 |
| 模型不可用 | `narrator.test.js`、`planner.test.js`、`research.test.js` | 402 余额不足、超时、非 JSON、未配置 Key、故障演练 llm_down → 规划降级为规则、叙述降级为模板，`fallback_reason` 写明原因；演练时不会真的请求模型 |

## 四、页面上的手工验证（故障演练）

服务启动后（`npm start`），研判请求体里的 `simulate` 字段支持以下演练项，页面「故障演练」开关与之一一对应（也可以直接用 curl 发请求）：

| 演练项 | 含义 | 手工验证时应看到 |
|---|---|---|
| `fuyao_down` | 扶摇接口全部失败 | 顶部提示“核心数据获取失败，本次不输出研判结论”；调用轨迹全部为失败；没有状态结论 |
| `fuyao_timeout` | 扶摇接口超时 | 调用轨迹显示“请求超时”；同上不输出结论 |
| `breadth_missing` | 全市场快照失败 | 状态名带“宽度未知”；数据缺口列出“全市场涨跌家数”；置信度下降 |
| `llm_down` | 大模型不可用 | 取数计划标注“规则规划”，结论标注“模板叙述”，并写明降级原因 |
| `stale` | 数据过期 | 置信度原因出现“数据时点过期” |
| `conflict` | 快照与日 K 冲突 | 出现“快照与日 K 收盘不一致”的冲突证据，置信度原因出现“数据冲突” |

```bash
curl -N -X POST http://localhost:8787/api/research \
  -H "Content-Type: application/json" \
  -d '{"index":"000001.SH","question":"现在市场是什么状态？","simulate":["breadth_missing"]}'
```

返回为 NDJSON 流：每行一个事件（`guard` / `stage` / `plan` / `step` / `report`），最后一行是完整报告。

**真实数据冒烟（人工，非自动化）**：开发期用扶摇真实接口（免费、不限累计调用）跑过一次全景研判：56 次调用、约 6~7 秒、2 次失败（即外部不开放的资金面接口，code=2004），其余维度正常；另跑过历史阶段追问、2026-06-15 历史时点 + 预测类提问、`fuyao_down` 三个场景，结果与上表预期一致。大模型账户余额为 0，真实模型路径未做线上冒烟。

## 五、已知未覆盖项

- **前端页面**：没有自动化的浏览器测试，页面渲染、证据抽屉、图表靠手工验证。
- **HTTP 服务层**：`server.js` 的按 IP 限流、NDJSON 流式输出、静态文件路径穿越防护没有单元测试。
- **真实大模型质量**：模型输出只用模拟数据验证了校验与降级逻辑；DeepSeek 真实输出的稳定性、长度、引用率未验证（开发期余额为 0）。
- **真实接口字段漂移**：模拟路由按文档与探测结果构造，若扶摇字段变更，需要靠真实冒烟发现。
- **时间边界**：研判交易日的 09:25 开盘前后切换逻辑依赖系统时钟，测试没有注入假时钟，只覆盖了“最近交易日在今天之前”的情形。
- **历史相似阶段的统计有效性**：只验证了结构与区间关系，没有评估特征选取与距离度量本身是否合理。
- 测试过程中发现的 7 个源码问题均已修复并补充 / 调整了用例，详见《AI 使用与验证记录》第五节。
