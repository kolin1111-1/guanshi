# 演示视频脚本（约 150 秒）

> 目标：展示一名用户完成核心任务——“搞清楚现在市场是什么状态、矛盾在哪、什么情况下要改判断”。全程直接操作产品，不讲 PPT。

| 时间 | 画面与操作 | 旁白要点 |
|---|---|---|
| 0:00–0:12 | 打开首页 | “观势只回答三件事：市场现在是什么状态、主要矛盾是什么、什么条件出现时判断要改。它不预测涨跌，也不给买卖建议。” |
| 0:12–0:30 | 点示例问题“指数在涨但我的股票都在跌…”，点「开始研判」；镜头给右侧「研判过程」 | “先由 AI 制定取数计划：每个工具为什么要调都写在这里。随后实时显示每次接口调用、耗时和失败情况。” |
| 0:30–0:55 | 状态卡：状态名、6 个维度标签、置信度及加减分原因 | “状态由公开的规则算出，AI 不能改判。置信度为什么是‘中’，每一项加分减分都列在这里，比如成交额预测接口外部不开放，完整度扣了分。” |
| 0:55–1:10 | 主要矛盾 + 结论三栏，点一个证据编号（如 B1），打开溯源抽屉 | “每条结论分成事实、归纳、不确定，并带证据编号。点开就能看到原始字段、接口、request_id 和时点，可以回到原始数据核对。” |
| 1:10–1:25 | 状态切换条件表 | “这是可观测的触发条件，不是预测：比如上证收盘站上多少点、上涨家数占比连续三天超过多少，判断就要改变。” |
| 1:25–1:40 | 点「继续研究 → 历史阶段对比」 | “继续研究时会换一组工具重新取数。这里找出近 5 年最相似的三个时点，只展示之后 20 天出现过的区间——有的跌、有的大涨，说明相似并不等于会重演。” |
| 1:40–2:05 | 输入“明天大盘会涨吗？现在该加仓吗？”，勾选故障演练「全市场快照失败」「数据过期」后研判 | “遇到预测和建议类问题，产品会说明边界并改写问题。数据缺失或过期时，页面置顶提示、状态名标注‘宽度未知’、置信度下降，不会静默给出看似正常的结论。” |
| 2:05–2:20 | 勾选「扶摇接口全部失败」后研判 | “核心数据拿不到时，整页不出结论，只展示失败原因和调用记录。” |
| 2:20–2:30 | 回到首页 | “数据来自扶摇 API；没有大模型或模型失败时，自动降级为规则规划加模板叙述，主链路不中断。” |

录制建议：浏览器宽度 ≥1280（侧栏与报告并排）；录制前先跑一次研判预热缓存，正式录制时等待更短。
