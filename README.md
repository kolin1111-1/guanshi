## 1. 快速启动

需要 Node.js ≥ 20，**零第三方依赖**（不需要 `npm install`）。

```bash
cp .env.example .env      # 填入 FUYAO_API_KEY；LLM_API_KEY 可留空
npm start                 # 打开 http://localhost:8787
npm test                  # 离线测试：模拟接口与模型，不访问网络、不消耗任何 Key
```

### 环境变量

| 变量 | 必填 | 说明 |
|---|---|---|
| `FUYAO_API_KEY` | 是 | 扶摇（同花顺金融数据 API）Key，登录 fuyao.aicubes.cn 后在「API Key 管理」签发。缺失时所有取数失败，页面如实显示，不会输出结论 |
| `LLM_API_KEY` | 否 | OpenAI 兼容接口的 Key。留空、余额不足或调用失败时，自动降级为「规则规划 + 模板叙述」，页面明确标注 |
| `LLM_BASE_URL` | 否 | 默认 `https://api.deepseek.com`；也可填通义、OpenAI、本地 Ollama（`http://localhost:11434/v1`）等 |
| `LLM_MODEL` | 否 | 默认 `deepseek-chat` |
| `PORT` | 否 | 默认 `8787` |

Key 只保存在服务端；浏览器拿不到 Key。`.env` 已被 `.gitignore` 排除。

## 2. 用户与问题

**目标用户**：有一定经验的个人投资者、投研新人、投顾和财经内容作者。他们每天都会被问到或自问“现在市场怎么样”，但手头的信息要么是零散的指标，要么是带观点的结论，很难回答：

1. 指数涨了，为什么大多数股票在跌？（指数与个股是否背离）
2. 现在是大盘风格还是小盘风格？行情集中在哪里？
3. 我今天的判断，明天在什么情况下就该改？

**核心任务**：输入一个指数、一个时点或一个问题，几秒内得到一份**有证据、有时点、有置信度、有切换条件**的状态研判，并能沿风格、行业、风险变量或历史阶段继续深挖。

**刻意不做**：涨跌预测、点位目标、买卖或仓位建议。用户问“明天会涨吗 / 该不该加仓”，产品会说明边界，并把问题改写为“当前状态 + 改变判断的条件”后照常研判。

## 3. 产品设计

### 3.1 一次研判的主链路

```
用户问题 / 指数 / 时点 / 追问方向
   │
   ├─① 合规预检：识别涨跌预测、投资建议、收益承诺 → 改写问题并提示
   ├─② 取数计划：大模型从 13 个注册工具中挑选并写理由（不可用时按规则规划）
   │      └ 白名单校验、补全必需工具、历史时点下标记“只有最新值”的工具
   ├─③ 调用工具：并发取数，每次调用记录 endpoint / 参数 / request_id / 数据时间 / 耗时 / 状态
   ├─④ 证据：原始字段 → 带来源、时点、单位、口径、状态（正常 / 缺失 / 部分缺失 / 过期 / 冲突）的证据
   ├─⑤ 状态框架（规则引擎，完全确定）：6 个维度评分与标签 → 综合状态、主要矛盾、置信度、切换条件
   ├─⑥ 叙述：大模型基于证据写“事实 / 归纳 / 不确定”三类结论 → 三道校验 → 不合格则降级为模板
   └─⑦ 报告：NDJSON 流式推送到前端，过程与结果同屏可见
```

### 3.2 页面上能看到什么

| 区块 | 内容 |
|---|---|
| 状态卡 | 综合状态名（如“趋势下行 · 普跌收缩”）、研判交易日、数据最新时间、6 个维度标签与评分、置信度及其加减分原因 |
| 主要矛盾 | 在多个候选张力中取最大者（如“近 20 日沪深300 跑赢中证1000 7.66 个百分点”），并列出次要矛盾 |
| 结论与证据 | 事实 / 归纳 / 不确定三栏，每条带证据编号，点击即看原始字段、接口、request_id、时点、口径 |
| 状态切换条件 | 每个维度“从什么切到什么”的可观测阈值、当前值和距离（如“收盘站上 3,775.84 点，距 +6.41%”） |
| 证据图表 | 指数与均线、涨跌分布、大小盘 / 成长价值比值、行业 20 日、两市成交额、涨跌停与封板率、宽基对比 |
| 历史相似阶段 | 近 5 年特征最相似的 3 个时点，以及之后 20 日的**区间**（最高 / 最低 / 期末），强调情景分布而非方向 |
| 证据清单 | 全部证据与数据缺口，按维度分组 |
| 研判过程（侧栏） | 规划来源（大模型或规则）、每个工具的理由与状态、调用明细（可核对 request_id）、耗时与缓存 |
| 故障演练 | 一键模拟接口全挂、超时、宽度缺失、模型不可用、数据过期、数据冲突 |

### 3.3 状态框架（规则全部公开，页面上点维度标签可看）

| 维度 | 输入 | 规则 |
|---|---|---|
| 趋势 | 目标指数日 K | 收盘相对 MA20(±0.5) + 相对 MA60(±0.75) + MA20 相对 MA60(±0.5) + 60 日涨跌/8%(±0.75)；≥1 上行趋势，≤−1 下行趋势，其余震荡 |
| 宽度 | 全 A 个股快照 | 0.6×(上涨占比−50%)/15% + 0.4×个股中位数涨跌/1.2%；≥0.8 扩散，≤−0.8 收缩，其余分化 |
| 流动性 | 上证指数 + 深证成指成交额 | 当日成交额在近 250 日的分位：≥70% 放量，≤30% 缩量 |
| 情绪 | 涨跌停统计、近 10 日基线、连板天梯 | (涨停−跌停)/50 + 0.6×(封板率−65%)/15% + 0.4×(涨停/近 10 日均值−1)/0.4 |
| 风格 | 中证1000 vs 沪深300、国证成长 vs 国证价值 | 20 日涨幅差 > 3 个百分点且比值在 60 日均线同侧 → 一方占优 |
| 行业 | 90 个同花顺二级行业 | 20 日收益横截面标准差的近期分位：≥70% 高分化，≤30% 趋同 |

- **综合状态** = 趋势 × 宽度 的 9 宫格命名；宽度缺失时显示“（宽度未知）”。
- **主要矛盾** 候选：趋势与宽度背离、权重股与典型个股背离、价量背离、情绪与趋势脱节、大小盘分化、成长价值分化、行业高分化；取张力最大者，低于阈值时说明“暂无突出矛盾”。
- **置信度** = 0.5×数据完整度 + 0.35×方向一致性 + 0.15×时效 − 0.1×冲突数 − 0.06×临界维度数 − 0.05×(强矛盾)；≥0.8 为高（且要求完整度 ≥80%），≥0.55 为中，其余为低。每一项加减分都在页面上列出。
- **切换条件** 是可观测阈值，不是预测：例如“上涨家数占比连续 3 个交易日 > 65% 且中位数 > +0.5% → 宽度切换为扩散”。

### 3.4 事实、归纳与不确定如何区分

| 类型 | 定义 | 例子 |
|---|---|---|
| 事实 | 原始字段，或对原始字段的确定性统计 | “全 A 上涨 1952 家、下跌 3498 家” |
| 归纳 | 规则对多条事实的判定，规则公开、可复现 | “宽度为「收缩」（评分 −0.82）：上涨占比 35.0%，中位数 −0.67%” |
| 不确定 | 评分接近阈值、信号冲突、数据缺口、事件影响未知 | “宽度评分 −0.82 接近阈值，标签可能在一两个交易日内翻转” |

## 4. AI 的角色

| 环节 | 谁来做 | 说明 |
|---|---|---|
| 取数规划 | 大模型（降级：规则） | 根据问题、对象、时点和追问方向挑选工具并写理由；输出经过白名单校验，必需工具由系统补全 |
| 指标计算、状态判定、置信度、切换条件 | **确定性规则** | 大模型不能修改任何数值或标签，保证同样的数据得到同样的结论 |
| 结论叙述 | 大模型（降级：模板） | 只能用给定证据写作，每条结论必须引用证据编号 |
| 输出校验 | 程序 | ① 引用的证据必须存在且不是缺失状态；② 结论里的每个数字都必须能在所引证据中找到（容差 1% / 四舍五入）；③ 涨跌预测、买卖 / 仓位建议、收益承诺类句子被拦截替换。通过校验的结论少于 3 条时整体降级为模板 |

设计取舍：在投研场景里，“说错一个数字”比“说得不够漂亮”代价高得多。所以让模型负责**理解问题和组织语言**，把**判断**交给可审计的规则，并用程序核对模型写出的每个数字。

> 开发期所用 DeepSeek 账户余额为 0，线上运行时走的是降级路径；大模型路径用模拟模型做了离线测试（见测试说明）。填入有余额的 Key 后即可切换，无需改代码。

## 5. 数据来源与口径

全部来自 **扶摇 · 同花顺金融数据 API**（`https://fuyao.aicubes.cn`，请求头 `X-api-key`）。时间均为北京时间。

| 工具 | 接口 | 用途 | 限制 |
|---|---|---|---|
| 交易日历 | `/api/a-share/calendar/trading-days` | 确定研判交易日、判断数据是否过期 | — |
| 指数快照 | `/api/a-share-index/prices/snapshot` | 最新点位，与日 K 交叉核对（差 > 0.3% 记为冲突） | 只有最新值 |
| 指数日 K | `/api/a-share-index/prices/historical-batch` | 10 个宽基 / 风格指数近 420 天：均线、波动率、风格比值、成交额分位 | 近 5 年 |
| 目标指数 5 年日 K | `/api/a-share-index/prices/historical` | 历史相似阶段 | 近 5 年 |
| 全市场宽度 | `/api/a-share/prices/snapshot`（分页，每页 3000） | 涨跌家数、中位数、分布 | 只有最新值；历史日宽度需 Parquet 全市场导出（未做） |
| 涨跌停统计 | `limit-up-statistics`、`limit-down-pool`、`limit-break-pool` | 涨停、跌停、炸板、封板率 | 可回看 1 年 |
| 近 10 日情绪 | 同上，逐日 | 情绪基线 | — |
| 连板天梯 | `/api/a-share/special-data/limit-up-ladder` | 最高连板高度 | 近 30 个交易日 |
| 行业 | `ths-index-list?tag=industry` + 日 K 批量 | 90 个同花顺二级行业的涨跌面、领涨领跌、离散度 | — |
| 估值 | 成分股列表 + `/api/a-share/valuations/snapshot` | 沪深300 / 中证500 / 创业板指成分股 PE(TTM)、PB(MRQ) 中位数、亏损占比 | **只有最新截面，无历史分位 → 不给“高估 / 低估”结论** |
| 题材与热度 | `limit-up-pool`、`hot-stock-list` | 涨停原因高频题材、热股榜 | 热榜只有最新值 |
| 重要事件 | `/api/news/flash/list?tag_id=21103` | A 股快讯标题与时间，作为事件线索 | 只有最新流；不做情绪打分 |
| 资金面 | `turnover-prediction-snapshot`、`etf-flow/net-inflow-historical` | 尝试获取成交额预测、宽基 ETF 净申购 | 实测返回 `2004`（同花顺 AI 客户端专用），作为**数据缺口**展示并下调完整度 |

**关键口径**

- 两市成交额 = 上证指数 turnover + 深证成指 turnover。已核对：深证成指 turnover 恰等于深市个股成交额之和；页面同时用个股快照加总做交叉核对（差 > 8% 标记待核实，实测差约 +0.8%）。
- 宽度样本 = 全 A（沪深京）个股，剔除当日无成交（停牌）个股。
- 估值为成分股中位数（剔除 PE ≤ 0 与空值），不是指数官方加权 PE。
- 快照取于收盘后时，标注为“收盘（快照取于 …）”；盘中取得则标注“盘中，非收盘值”。

**缺失、冲突、过期、失败时的处理**：不补零、不用最新值冒充历史值，也不静默跳过。缺失项进入“数据缺口”，降低完整度和置信度；指数日 K 这类核心数据缺失时，**整页不输出研判结论**，只展示失败原因和调用记录。

## 6. 合规边界

- 输入侧：识别“会不会涨 / 跌、点位、目标价、该不该买卖、仓位、抄底、稳赚”等表述 → 提示边界，改写为状态研判问题。
- 输出侧：拦截“将 / 有望 / 大概率 + 上涨 / 下跌 / 反弹”、“建议买入 / 加仓”、“仓位”、“目标价”、“稳赚”等句子，替换为“〔已拦截〕”并在校验记录中展示。
- 历史相似阶段只展示之后 20 日的**区间**，并注明“历史相似不代表未来重演”。
- 页脚常驻免责声明；不涉及任何用户画像或持仓数据。

## 9. 部署

纯 Node 服务，任何能运行 `node server.js` 的平台都可以：在平台上设置 `FUYAO_API_KEY`（可选 `LLM_*`）环境变量，启动命令 `npm start`，健康检查路径 `/api/health`。仓库附带 `render.yaml`（Render）与 `Dockerfile`。
